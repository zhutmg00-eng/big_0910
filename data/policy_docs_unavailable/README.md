# 抓取失败的政策文件（不参与检索）

本目录存放**抓取到但不可用**的条目：内容是政府网站的错误页或门户导航，
没有任何政策正文。它们被移出 `data/policy_docs/`，因此**不进入知识库**。

保留在此而不是删除，是为了让「我们试过、失败在哪」这件事可追溯——
直接删掉会让人以为漏收了这份文件。

## 为什么不能留在 `data/policy_docs/`

`src/rag/__init__.py` 的 `ingest_directory()` 会把这个目录下所有 `.md`
切成政策分块。错误页一旦入库，它的导航文字（「返回首页」「省生态环境厅」
「页面不存在」）就变成"看起来像条款"的分块，检索命中后表现为"有政策依据"，
实际全是网站骨架。这比直接缺一份文件危险得多。

现已在入库处加 `detect_error_page()` 守卫：命中「页面不存在」「您访问的地址
有错」等标记的文件会被拒绝入库，并打 WARNING 日志、在返回结果里列入
`rejected` 字段。

## 影响

- 知识库规模由 40 份 / 287 块降为 38 份 / 283 块（见 `README.md`）。
- 负例集 NEG_N02 / NEG_N03 原本把 404 页的分块当作"库内依据"，
  已重新锚定到真实条款（`暂行条例国新办政策解读_吹风会.md`、
  `2025年全国碳市场运行情况.md`），见 `docs/rag_benchmark/negative_benchmark_30_questions.json`。

## 要恢复这两份文件

1. 从官网拿到正确 URL，确认页面正文含「第一条」等条文；
2. 存成 Markdown 放回 `data/policy_docs/`，头部写 `**发布时间**: YYYY年M月D日`；
3. `python scripts/ingest_policy_docs.py --force`；
4. 重跑 `python scripts/evaluate_rag_benchmark.py` 并同步更新文档中的知识库规模。

守卫测试：`tests/test_kb_no_error_pages.py`
