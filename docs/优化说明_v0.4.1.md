# 2. 碳价窗口：一个比“90 行 vs 90 日”更大的问题

交接文档发现了两个“近 90 日均价”不一致（90.72 与 78.67），建议统一为“90 个交易日”。排查后发现根源不同：

- 碳价序列是**周频**数据，274 行中 201 行（73.4%）是插值；
- 旧版情景成本用 `tail(90)` 取“末 90 行”，实际覆盖约 **90 周（约 1.7 年）**，把 2024—2025 年 50 多元的低价混了进来；
- 所以改成“90 个交易日”同样不对——这份数据里根本没有逐日行情。

v0.4.1 的做法：窗口按**近 90 个自然日**，只用**真实成交点**，同时返回观测点数。

| 指标 | v0.4 | v0.4.1 |
|---|---|---|
| 近 90 日均价（统计页） | 90.72（含插值） | **92.78**（7 个真实成交点，2026-05-15 至 2026-08-11） |
| 近 90 日均价（情景成本） | 78.67（实为近 90 周） | **92.78**（与统计页一致） |
| Fleet-Alpha 情景成本区间 | 13.73 万 – 26.42 万元 | **22.65 万 – 26.42 万元** |
| 波动指标 | “波动率” 1.69% / 2.37%（不规则间隔上的 pct_change，含义不清） | **价格离散度 CV 6.62%** |

答辩时如被问到：“情景成本只用近 90 天的真实成交价，插值点只用来画趋势线。”`docs/derived_metrics.json` 已通过 `scripts/gen_derived_metrics.py` 重新生成，没有手改。

# 3. 检索评测：知识库变了，数字也要变

| 方案 | KB 37 份 / 268 块（v0.4 快照） | KB 39 份 / 281 块（v0.4.1 当前） |
|---|---|---|
| F 三路 RRF（默认） | MRR 0.433 · R@10 80.0% | MRR 0.411 [0.300, 0.531] · R@10 80.0% |
| D BM25 | MRR 0.440 · R@10 70.0% | MRR 0.425 · R@10 67.5% |
| B 纯向量（中文嵌入） | MRR 0.272 · R@10 57.5% | MRR 0.259 · R@10 57.5% |
| C 加权重排（v0.3） | MRR 0.490 · R@10 72.5% | MRR 0.490 · R@10 72.5% |

- 新增的 2 份文档对 40 道旧题来说是干扰项，MRR 小幅下降，仍在置信区间内；默认方案 Recall@10 保持 80%。
- **如实说明**：三路 RRF 的优势在 Top-10 召回；它的 MRR 与字面启发式、BM25 没有显著差异（Holm 校正 p>0.05），只显著优于纯向量和两路 RRF。
- 交接包说现有知识库是 43 份 / 375 块。那 4 份额外文档不在 GitHub 上，我拿不到，所以这里的数字对应 39 份 / 281 块。如果你本地确实是 43 份，请在本地运行 `python scripts/evaluate_rag_benchmark.py` 重测，再把那组数字写进 PPT。
- 知识库扩充后应同步增加针对新文档的评测题（例如新能源重卡目标、轻型货车油耗限值），否则新文档的价值测不出来，只会表现为噪声。

# 4. 交接手册中已修正的错误

1. “配置了 API Key 也不会调用 LLM”——**不对**。回答生成与检索模式无关：有 Key 就调用大模型，没有 Key 才返回抽取式回答。
2. “没有独立的 sources 字段”——**不对**。`/api/ask` 一直返回结构化的 `retrieved_sources`。
3. “卸载 ChromaDB 作为演示方案”——不再需要。现在自动降级已经实现，答辩用完整模式，降级只用于兜底。
4. 知识库数量统一为当前产品版本（39 份 / 281 块）。
