## 一、项目背景与系统整体架构

我国交通运输领域碳排放占全国终端碳排放总量的 10% 左右，其中道路货运物流车辆因高频次、大负荷运行，是交通降碳的“硬骨头”。但在微观运营实务中，广大中小货运车队普遍面临“缺乏油料台账算不清碳”、“看不懂复杂多变的双碳法规”、“不敢贸然做新能源投资决策”三大痛点。

本项目针对上述痛点，开发了“物流碳排放与减排情景决策助手”科研原型系统。系统全层级技术架构如下图所示：

系统自上而下涵盖三大层次：
1. **多模态接入与呈现层**：包含高性能异步 API、符合 DeepSeek Harness 官方规范的生态插件 `dsh-plugin-carbon-asset`（注册 6 大专业工具），以及基于 GenUI 的自包含实证交互展板（彻底抛弃脆弱的 Streamlit 架构）；
2. **核心模型与计算引擎层**：涵盖微观活动水平直接排放基线、低满载率动态惩罚、多情景新能源替代与 TCO 联动、Scope 2 外购电间接排放以及营运货物周转量（万吨公里）碳强度对标；
3. **科学问题实证支撑体系**：紧扣三大递进科学问题（RQ1、RQ2、RQ3），以 4.5 万辆真实公开台账、40 题双盲审校政策基准与二维扰动敏感性网格构成闭环证据链。

## 二、我们做了什么：全景研发与核心成果

在中期研发阶段，团队拒绝“调用商业大模型做简单对话包装”的低质内卷，扎实落地了以下六大核心工作：

### 1. 微观车队碳排放基线核算引擎 (`src/engine/calculator.py`)
- **自下而上活动水平模型**：依据国家发展改革委《陆路交通运输企业温室气体排放核算方法与报告指南》，建立公式：
  $$E = \sum_{i} \frac{n_i \times d_i \times \text{EF}_i \times \text{LF}_i}{1000}$$
  精准支持重型柴油车、中型柴油车、轻型柴油车、微型汽油车、LNG货车与纯电动货车等多动力车型；
- **动态满载率惩罚机制**：创新引入满载率调节因子 $\text{LF}_i = 1 + 0.15 \times (0.75 - l_i)$（当满载率 $l_i < 0.75$ 时），科学量化回程空驶与轻载导致的单位周转能耗上浮。

### 2. 新能源替代 TCO 经济账与减排决策闭环 (`src/engine/tco.py` & `reduction.py`)
- 构建涵盖**初始增量购置投资 ($\Delta\text{CAPEX}$)**、**年均能耗节省 ($\Delta\text{OPEX}$)**、**维保差额**的综合总拥有成本模型；
- 计算新能源替换的**静态投资回收期（年）**与**吨碳减排边际成本（MAC, Marginal Abatement Cost）**；
- 实现了情景优化与基线物理核算完全一致的“**减排物理守恒**”。

### 3. 垂直领域小样本政策问答 RAG 知识库与重排引擎 (`src/rag/`)
- 全量爬取并人工清洗 37 份官方顶层条例、配额方案、MRV指南及重型商用车油耗强标（如 GB 30510-2024）；
- 严格遵循“**入库即定块**”标准，去除抓取页脚与重复行噪音，规范切分为 **268 个规范 Chunk** 并固化唯一物理 ID；
- 研发“语义向量余弦初筛 + 中文标题与领域词特征混合重排”引擎，无需昂贵微调即实现法条精准锚定。

### 4. 真实车队基准复核与 40 题基准评测集构建 (`docs/rag_benchmark/` & `data/raw/real_fleets/`)
- 采集顺丰速运（干支综合）、中通快递（纯干线长途）、京东物流（城配轻型）、生鲜冷链（特种低满载）共 **45,035 辆真实车辆公开台账**（ESG 报告 / 车载 T-Box）；
- 编制自主研发的 **40 题双碳法规评测集**（涵盖配额、条例、MRV、CCER、地方试点、GB强标 6 大维度，含 4 道反事实合规负例）；
- 完成双人背靠背双盲审校，取得 **Cohen's Kappa = 1.00** 的极高一致性。

### 5. 外购电间接排放 (Scope 2) 与货运周转量碳强度对标 (`src/engine/indirect_emission.py`)
- 依据生态环境部、国家统计局《关于发布2023年电力二氧化碳排放因子的公告》（2025年第47号），收录全国平均（0.5306 kgCO2/kWh）、全国化石电力（0.8273）及 **31 个省市最新电网排放因子**；
- 测算纯电货车真实耗电量（轻卡 35 kWh/100km、重卡 150 kWh/100km）引起的 Scope 2 间接排放，得出“以电代油真实净减排量”；
- 引入 GB 1589 额定吨位载重折算，计算**货物周转量（万吨公里）**与**营运碳排放强度（gCO2 / t·km）**，对标交通达峰规划目标。

### 6. DeepSeek Harness (`dsh`) 官方生态插件交付 (`packages/dsh-plugin-carbon-asset/`)
- 基于 Cordis 微内核架构开发标准插件，注册包含碳核算、TCO、情景模拟、政策问答、横向对标及周转量强度在内的 **6 大专业 Agent 工具**；
- 实现 **HTTP 在线微服务与本地 Python CLI 进程透明降级的双模通信机制**，实现即开即用、无需人工启动常驻服务。

## 三、遇到了什么关键问题：实事求是的学术与工程瓶颈

在大创研发与实证推进过程中，团队实事求是地面临了五个深层次的学术与技术瓶颈：

```
┌────────────────────────────────────────────────────────────────────────┐
│               【研发推进中所遭遇的核心瓶颈与技术挑战】                 │
├────────────────────────────────────────────────────────────────────────┤
│  挑战 1：数据有限性 ── 中小车队无油料发票，宏观估算是否存在低估失真？  │
│  挑战 2：语义稀疏性 ── 通用向量基座在面对法律编号与长尾实体时长尾失效？│
│  挑战 3：合规幻觉风险 ── 面对车队涉碳违法提问，大模型缺乏合规拒答机制？│
│  挑战 4：物理不守恒 ── 多工况车队新能源替换时，不同满载率导致基准分歧？│
│  挑战 5：平台管道陷阱 ── Windows 操作系统 GBK 编码与子进程挂起卡死？   │
└────────────────────────────────────────────────────────────────────────┘
```

1. **瓶颈一（数据有限条件下的精度与低估风险）**：  
   微观承运商普遍缺乏加油发票明细，行业曾质疑“仅凭车型与行驶里程估算出的排放量是否失真严重？若模型低估排放，企业面临被货主或监管指控‘漂绿’的法律风险”。
2. **瓶颈二（专业法规长尾实体在通用向量空间严重弥散）**：  
   测试发现，未经微调的通用轻量向量基座在面对“GB 30510-2024 限值”、“六氟化二碳折算”、“20% 缺口率上限豁免”等高度特定的中文实体时，余弦相似度区分度极低，纯向量检索的倒数排名倒数均值（MRR）**仅为 0.0411**，导致法条检索答非所问。
3. **瓶颈三（大模型在政策解读中的“反事实法律幻觉”）**：  
   车队管理者常有错误常识（如“自购纯电车队能不能开发 CCER 卖碳赚钱？”或“公路货运要交多少全国配额？”）。由于缺乏拒答防护，通用 LLM 极易顺应用户诱导，捏造虚假的准入门槛和交易流程。
4. **瓶颈四（多工况车队替换时的基准漏算与物理不守恒）**：  
   当基线车队包含多个同车型但不同满载率的工况组时（如组A重卡满载率0.85、组B重卡满载率0.55），早期代码直接采用单一默认排放因子扣减，导致 TCO 测算的减排量与基线核算差额出现口径分歧，违背物理守恒定律。
5. **瓶颈五（跨平台编码与子进程通信挂起风险）**：  
   在没有启动 HTTP 服务的无头场景下，Node.js 插件通过子进程调用 Python CLI 桥接引擎时，Windows 默认控制台代码页（GBK）导致多字节中文字符管道断裂；且一旦大模型传入异常超长 payload，子进程容易永久死锁挂起。

## 四、我们是怎么解决的：技术攻关、算法重构与实证效果

面对上述瓶颈，团队逐一开展了针对性算法重构与实验验证：

### 1. 解决瓶颈一：建立真实台账对比矩阵，证实“恒定正偏的保守性机制”
- **技术解决**：
  团队没有做理论推演，而是收集了涵盖顺丰（干支混合）、中通（纯干线）、京东（城配）与生鲜冷链（低满载重卡）四大真实场景共 45,035 辆真实运营车辆的公开台账，逐一比对自下而上活动水平估算值（$E_{\text{model}}$）与企业燃油台账真实值（$E_{\text{fuel}}$）。
- **实证效果与证据**：

### 2. 解决瓶颈二与三：提出混合重排检索机制，固化反事实负例合规拒答
- **技术解决**：
  1. 放弃纯依赖向量相似度的单一架构，构建 **“ChromaDB 向量初筛候选集 + 中文标题覆盖率与领域词先验混合重排”** 机制；
  2. 重构重排打分算法，动态识别 CCER 自愿减排、地方试点、GB 强标与配额分配等领域关键词，避免“只要 query 包含物流两字就盲目匹配交通规划”的经验偏见；
  3. 在 40 题标准库中重点设置 Q04（公路货运非全国履约主体）、Q24（自购纯电车队不可直接开发 CCER）、Q29（自备电厂不重复履约）、Q30（广东未纳管货运）等反事实负例。

### 3. 解决瓶颈四：重构多工况分组逻辑，建立参数网格敏感性矩阵
- **技术解决**：
  1. 重构 `src/engine/reduction.py`，在计算新能源车辆单车替换减排量时，引入单车实际满载率动态修正因子 `load_adj = calculate_load_adjustment(g.load_factor)`，消除跨工况替换带来的口径分歧；
  2. 建立 **满载率扰动 (-20% ~ +20%) × 年均行驶里程扰动 (-20% ~ +20%)** 的 $5 \times 5$ 二维参数扰动敏感性网格模型。

### 4. 解决瓶颈五：PEP 540 UTF-8 Mode 强化与 30 秒超时熔断
- **技术解决**：
  1. 在 Node.js 插件桥接层 (`bridge.ts` & `dist/bridge.js`) 中，除原有 `PYTHONIOENCODING: 'utf-8'` 外，全面注入 Python PEP 540 标准模式环境变量 `PYTHONUTF8: '1'`，彻底消除 Windows 平台在中文控制台下的编码截断；
  2. 为子进程异步调用加入 30 秒定时中断保护（`timer = setTimeout(() => proc.kill(), 30000)`），若子进程超时则自动熔断并向大模型返回结构化错误说明，彻底杜绝会话挂起；
  3. 扩充插件工具至 6 项（新注册 `carbon_turnover_evaluate`），将 Scope 2 外购电电网因子与吨公里强度模型全面向 DeepSeek 智能体开放。

## 五、第三方同行专家双盲评审体系背书

| 评估维度 (各占 25% 权重) | 专家 A (高校博导) | 专家 B (企业总监) | 维度均分 | 专家定性评价要点 |
|---|:---:|:---:|:---:|---|
