## 四、交叉编码器精排实验（独立运行）

配置：rrf3 召回 top-20 → `BAAI/bge-reranker-base` 精排，段落截断 300 字。结果 MRR 0.3645、Recall@1 22.5%、Recall@10 70.0%，CPU 推理约 9.1 秒/题（2 vCPU 无 GPU）。精排后指标反而低于不精排的 rrf3（MRR 0.433），原因可能是段落被截断后丢掉了关键条款，而且 base 模型对长段落中文法规的区分度有限。因此精排默认关闭，通过环境变量 RERANKER_MODEL 开启，留作 GPU 环境下的扩展实验。

## 五、结论与局限

1. **v0.3 纯向量组指标极低的根因是嵌入模型选错**：ChromaDB 默认的 all-MiniLM-L6-v2 是英文模型。换成中文 bge-small-zh 后纯向量 MRR 明显提升（见第三节），说明问题不在“向量检索不适合政策文本”。
2. **默认方案改为三路 RRF（F 组）**：BM25（jieba 分词）、中文稠密向量、v0.3 字面规则三路检索按名次融合（RRF，k=60，原论文推荐值）。三路权重为 BM25 0.6 : 向量 0.1 : 字面规则 0.8，不是等权——等权融合的 MRR 只有 0.4112，低于它要取代的 v0.3 方案，是在同一评测集上做权重诊断时才发现的（该数字与权重调优同源，不作独立证据）。权重稳健性用 5 折交叉验证单独检查：折内独立选出的向量权重全部落在 0.05–0.2，见 `rrf_weight_cross_validation.md`。F 组 Recall@10 在全部方案中最高。
3. **如实交代的负面结果**：① 两路 RRF（E 组）的 MRR 不如 BM25 单路，原因是稠密向量对“情景描述型”长问题仍然偏弱，融合时拖低了排序；② v0.3 字面规则里有几条针对主题写的加权规则，存在对评测集过拟合的风险，所以 v0.4 只把它当作融合中的一路信号，不再让它主导打分；③ 交叉编码器精排在 CPU 上每题约 9 秒，指标反而下降，所以默认关闭；④ 三路 RRF 相对 v0.3 与 BM25 的差距经 Holm 校正后均不显著，只能说“不劣于”，不能说“显著更好”。
4. **局限**：评测集只有 40 题，置信区间较宽，多数两两差异经多重比较校正后不显著。下一步计划把评测集扩到 100 题以上，按“单一事实型 / 情景推理型”分层评测，并加入生成质量评测（忠实度、引用准确率）。
